# Inventory Management API

A production-style REST API for managing inventory — categories, products, suppliers, and per-product supplier relationships — with a full stock movement audit trail, stateless JWT authentication, and role-based access control built on Spring Boot 4 and PostgreSQL.

## Features

- **Authentication & Authorization** — stateless JWT-based auth (HS256, 1-hour expiry) with `ROLE_ADMIN` / `ROLE_STAFF` roles, method-level security guards, and BCrypt password hashing.
- **Categories** — create, list, retrieve, and delete product categories with automatic URL-friendly slug generation and unique-name enforcement.
- **Products** — full product lifecycle with auto-generated SKUs (`CATEGORYPREFIX-PRODPREFIX-XXXXX` format), status tracking (`ACTIVE`, `INACTIVE`, `DISCONTINUED`), unit cost, stock quantity, and reorder level.
- **Suppliers** — supplier directory with contact details (validated Philippine mobile format: `09XXXXXXXXX` or `+639XXXXXXXXX`).
- **Product–Supplier Links** — many-to-many relationships enriched with per-link data: supplier-specific SKU and unit cost, keyed to the product–supplier pair.
- **Stock Movements** — immutable audit log of every stock change: `STOCK_IN`, `STOCK_OUT`, and `ADJUSTMENT` types, recording previous/new quantities, the acting user, reason, and optional reference.
- **Partial updates** — PATCH endpoints use [`JsonNullable`](https://github.com/OpenAPITools/jackson-databind-nullable), correctly distinguishing between "field not sent" and "field explicitly set to null".
- **JPA Auditing** — automatic `createdAt` / `updatedAt` timestamps on all mutable entities.
- **UUID Primary Keys** — all entities use UUID string identifiers generated by Hibernate.

## Data Model

```
Category 1 ──────< Product  >────── Supplier
                 │                     │
                 │        (join entity with payload)
                 │                     │
                 └─── ProductSupplier ─┘
                 (joined on product_id + supplier_id,
                  carries supplierSku + unitCost)

StockMovement ──> Product (nullable)
StockMovement ──> User (nullable)

User 1 ──< user_roles > values: ROLE_ADMIN | ROLE_STAFF
```

| Entity | Table | Key attributes |
|---|---|---|
| **Category** | `categories` | `name` (unique, ≤50), `slug` (unique, auto-generated), `description` (≤360) |
| **Product** | `products` | `name` (unique, ≤150), `sku` (unique, auto-generated), `description` (≤700), `unit`, `unitCost` (10,2), `stockQuantity`, `reorderLevel`, `status` |
| **Supplier** | `suppliers` | `name`, `contactPerson`, `email`, `phone` (PH mobile regex), `address` |
| **ProductSupplier** | `product_suppliers` | unique pair (`product_id`, `supplier_id`), `supplierSku`, `unitCost` — per-link pricing |
| **StockMovement** | `stock_movements` | `type`, `quantity`, `previousQuantity`, `newQuantity`, `reason`, `reference`, `createdAt` — immutable audit record |
| **User** | `users` | `name`, `email` (unique), `password` (BCrypt), roles in `user_roles` |

## Getting Started

### Prerequisites

- **JDK 25**
- **PostgreSQL** (running locally or reachable instance)
- Git

The Maven wrapper (`mvnw` / `mvnw.cmd`) is included, so Maven itself is not required.

### Configuration

1. Create a database in PostgreSQL (e.g. `inventory_db`).

2. Copy the environment template and fill in your values:

   ```bash
   cp .env.example .env
   ```

   | Variable | Description |
   |---|---|
   | `DB_URL` | JDBC URL, e.g. `jdbc:postgresql://localhost:5432/inventory_db` |
   | `DB_USERNAME` | PostgreSQL username |
   | `DB_PASSWORD` | PostgreSQL password |
   | `JWT_SECRET_KEY` | HMAC-SHA256 secret for signing JWTs (HS256 — use a strong secret ≥ 32 bytes) |
   | `CLOUDINARY_CLOUD_NAME` | Cloudinary config (reserved for upcoming integration) |
   | `CLOUDINARY_API_KEY` | Cloudinary config (reserved for upcoming integration) |
   | `CLOUDINARY_SECRET_KEY` | Cloudinary config (reserved for upcoming integration) |

   The application loads `.env` from the project root at startup via `spring.config.import`. Tokens expire after **1 hour** (`jwt.expiration_ms` in `application.properties`).

3. Schema management is handled by Hibernate:

   ```
   spring.jpa.hibernate.ddl-auto=update
   ```

   Tables are created/updated automatically on startup — no migration tool needed for development.

### Running the Application

```bash
# Linux / macOS
./mvnw spring-boot:run

# Windows
.\mvnw.cmd spring-boot:run
```

The API starts on **http://localhost:8080**.

## Authentication

All endpoints except `POST /api/v1/auth/login` (and Spring's `/error`) require a valid JWT.

**1. Log in** to get a token:

```bash
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{ "email": "admin@dojo.com", "password": "testPass" }'
```

**2. Send the token** as a Bearer header on every subsequent request:

```bash
curl http://localhost:8080/api/v1/products \
  -H "Authorization: Bearer <your-token>"
```

**3. Role rules:**

| Role | Access |
|---|---|
| Unauthenticated | Only `POST /api/v1/auth/login` |
| `ROLE_STAFF` | All inventory endpoints (categories, products, suppliers, product-suppliers, stock movements) |
| `ROLE_ADMIN` | Everything, including `/api/v1/users` (via `@PreAuthorize("hasRole('ADMIN')")`) |

Missing/invalid tokens return **401**; insufficient roles return **403**, both as JSON.

## API Reference

Base URL: `http://localhost:8080/api/v1`

Legend: 🔓 Public · 🟦 Authenticated · 🟥 ADMIN only

### Response Envelope

All responses are wrapped in a consistent envelope (`ApiResponse<T>`); null members are omitted:

```json
{ "message": "...", "data": { ... } }
```

- Read endpoints: `data` only (no `message`)
- Mutation endpoints: `message` + `data`
- Deletions: `message` only

### Auth

| Method | Path | Access | Description |
|---|---|---|---|
| 🔓 POST | `/auth/login` | Public | Authenticate and receive a JWT |
| 🟦 GET | `/auth/me` | Authenticated | Current user info |

Request body — `POST /auth/login`:

```json
{
  "email": "admin@dojo.com",
  "password": "testPass"
}
```

Response:

```json
{
  "message": "Login Successful",
  "data": {
    "token": "eyJhbGciOiJIUzM4NCJ9...",
    "user": {
      "id": "3f2c...",
      "name": "Dojo Admin",
      "email": "admin@dojo.com",
      "roles": ["ROLE_ADMIN"],
      "createdAt": "2026-01-01T00:00:00.000+00:00",
      "updatedAt": "2026-01-01T00:00:00.000+00:00"
    }
  }
}
```

### Categories

| Method | Path | Access | Description |
|---|---|---|---|
| 🟦 GET | `/categories` | Authenticated | List all categories |
| 🟦 GET | `/categories/{categoryId}` | Authenticated | Get one category |
| 🟦 POST | `/categories` | Authenticated | Create a category (201) |
| 🟦 DELETE | `/categories/{categoryId}` | Authenticated | Delete a category |

- `description` — optional, ≤ 360 chars.

Response (201):

```json
  "data": {
    "id": "a1b2...",
    "name": "Electronics",
    "slug": "electronics",
    "description": "Gadgets, devices and accessories",
    "createdAt": "...",
    "updatedAt": "..."
  }
}
```

### Products

| Method | Path | Access | Description |
|---|---|---|---|
| 🟦 GET | `/products` | Authenticated | List all products |
| 🟦 GET | `/products/{productId}` | Authenticated | Get one product |
| 🟦 POST | `/products` | Authenticated | Create a product (SKU generated automatically) |
| 🟦 PATCH | `/products/{productId}` | Authenticated | Partial product update (`JsonNullable`) |
| 🟦 DELETE | `/products/{productId}` | Authenticated | Delete a product |
| 🟦 PATCH | `/products/{productId}/stock` | Authenticated | Stock in/out — records a stock movement |

Request body — `POST /products`:

```json
{
  "categoryId": "a1b2c3d4-e5f6-...",
  "name": "Logitech MX Master 3S",
  "description": "Wireless performance mouse with Quiet Clicks and 8000 DPI sensor.",
  "unit": "piece",
  "unitCost": 99.99,
  "stockQuantity": 150,
  "reorderLevel": 25,
  "status": "ACTIVE"
}
```

Field constraints:

| Field | Constraints |
|---|---|
| `categoryId` | required, must be a valid UUID of an existing category |
| `name` | required, 2–150 chars, unique |
| `description` | required, 10–700 chars |
| `unit` | required |
| `unitCost` | required, ≥ 0.01 |
| `stockQuantity` | required, ≥ 0 |
| `reorderLevel` | required, ≥ 0 |
| `status` | required — `ACTIVE`, `INACTIVE`, or `DISCONTINUED` |

Update stock — `PATCH /products/{productId}/stock`:

```json
{
  "type": "STOCK_IN",
  "quantity": 40,
  "reason": "Restock from supplier #1234",
  "reference": "PO-2026-001"
}
```

- `type` — `STOCK_IN` or `STOCK_OUT` (a stock movement of the product's quantity is recorded with previous/new quantities and the acting user).
- `quantity` — must be > 0. `STOCK_OUT` beyond available stock returns **400** ("Insufficient stock quantity").
- `reason` — required, ≤ 250 chars.
- `reference` — optional.

Response confirms the update and echoes the resulting product (with `stockQuantity` and `previousQuantity`/`newQuantity` captured in `stock_movements`).

| 🟦 GET | `/stock-movements/{stockMovementId}` | Authenticated | Single movement |

Response — array of movement records:

```json

      "id": "d4e5...",
      "type": "STOCK_IN",
```

| Method | Path | Access | Description |
|---|---|---|---|
| 🟥 GET | `/users` | ADMIN | List all users |
| 🟥 GET | `/users/{userId}` | ADMIN | Get one user |
| 🟥 POST | `/users/register` | ADMIN | Create a user (201) |
| 🟥 DELETE | `/users/{userId}` | ADMIN | Delete a user |

Request body — `POST /users/register`:

```json
{
  "name": "Maria Santos",
  "email": "maria@dojo.com",
  "password": "Str0ngPass!",
  "confirmationPassword": "Str0ngPass!",
```

- `role` — `ROLE_ADMIN` or `ROLE_STAFF`.
- Emails must be unique.

Response (201): `{ "message": "User registered successfully" }`

## Error Handling

A global `@RestControllerAdvice` (`GlobalExceptionHandler`) shapes all errors:

**Validation errors (400)** — per-field map:

```json
{
  "timestamp": "2026-01-05T09:30:00.000+00:00",
  "status": 400,
  "error": "Validation failed",
  "errors": {
    "name": "Product name is required",
    "unitCost": "Unit cost must be greated than 0"
  }
}
```

**Resource not found (404)**:

```json
{
  "timestamp": "2026-01-05T09:30:00.000+00:00",
  "status": 404,
  "error": "Not Found",
  "message": "Product with id <id> not found"
}
```

**Auth failures** — returned as JSON by the security filter chain:

```json
// 401 — missing/invalid token
{ "status": 401, "error": "Unauthorized", "message": "Authentication is required to access this resource" }

// 403 — insufficient role
{ "status": 403, "error": "Forbidden", "message": "You do not have permission to access this resource" }
```

**Bad credentials** (failed login) return **400**; business rule violations (e.g. insufficient stock, duplicate SKU) return **400** with a descriptive message.
